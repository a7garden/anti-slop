# Visual audit evaluation

Use [visual-audit-cases.json](visual-audit-cases.json) with the [offline fixture](visual-audit-fixture.html) and [festival control](visual-style-control.html). These are illustrative screens. The approval and rate disclosures show local details only. The fixtures perform no payments, bookings, or persistence.

1. Open each selected `target` as a local file with JavaScript enabled, or from a loopback static server. Capture the configured region at the listed CSS viewport. `capture.width_css_px` and `height_css_px` set that viewport, not the exported region dimensions; record the actual image size separately. Record actual viewport, capture dimensions, zoom, theme, state, and renderer where known. Preserve native-resolution captures. If the tool cannot reproduce the configured conditions, record the actual ones and limit comparisons accordingly. For the table, distinguish the start-of-scroll capture from any separately observed scrolled state.
2. Run at least three fresh independent repetitions per selected scenario, using its `prompt`, target or capture, and actual environment facts. Supply one scenario per run. Keep `reviewer_only`, paired images, prior reports, and expected findings out of execution inputs. With only supplied captures, record the review as capture-based. For independent rendered inspection, preserve the observation, measurements actually taken, and relevant source or tool evidence. A source value alone cannot establish the rendered result.
3. Review against the anchors and preservation conditions after execution. Separate measurable observations such as region bounds, local overflow and measured contrast from contextual judgments such as which emphasis supports the decision. Judge each identified issue by region, visible relationship, task, likely consequence, and supported repair. Record omissions, unsupported findings, capability or preservation mistakes, and material gaps. Color, card, and whitespace quotas are irrelevant to this evaluation.
4. Compare the approval pair under matching recorded conditions and verify that the repair changes the visual relationship while preserving the amount, decision consequence and native preview disclosure. The pair shares content and markup. A capture comparison can establish a changed relationship. Disclosure interaction and accessibility require their own evidence. Run the narrow table and festival controls to check whether the review preserves useful density and deliberate expression. The narrow table can support a bounded column-width or row-identification finding; preservation does not mean a mandatory clean verdict.

Report the cases, repetition counts, revision, capture and tool limits, and reviewer judgments. Use the [focused evaluation protocol](behavior-evaluation.md#focused-rendered-design-evaluations) and the [visual audit method](../references/visual-audit.md). The fixture and answer key define a test, with actual executions and outcomes reported separately.
